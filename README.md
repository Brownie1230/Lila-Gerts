# Lila Gerts

Шаблон сайта для керамических фигурок и свечей ручной работы, плюс библиотека дизайн-скилов, на
которой он собран.

- **`index.html`** — страница. Сборка не нужна.
- **[DESIGN.md](DESIGN.md)** — палитра, шрифты, сетка, правила, бриф заказчицы.
- **[SKILLS.md](SKILLS.md)** — 168 дизайн-скилов и из какого коммита каждый взят.
- **[CLAUDE.md](CLAUDE.md)** — какой скил брать под какую задачу.

## Посмотреть

```bash
python3 -m http.server 8000
# откройте http://localhost:8000
```

## Выложить на GitHub Pages

Страница целиком статическая, все пути относительные, поэтому Pages раздаёт её как есть.
В репозитории уже лежит `.nojekyll`, чтобы Jekyll ничего не трогал.

1. Запушить ветку в `Brownie1230/Lila-Gerts`.
2. Settings → Pages → Source: **Deploy from a branch**, ветка и папка `/ (root)`.
3. Через минуту сайт открывается по адресу `https://brownie1230.github.io/Lila-Gerts/`.

Адрес публичный: клиенты просто открывают ссылку, ничего не скачивая.

Через `file://` открывать не стоит: иконки подключены как `<use href>`, браузер их заблокирует по
политике одного источника.

## Что на странице

Шесть секций: первый экран, бегущая строка с четырьмя обещаниями, каталог из трёх направлений,
полноэкранный блок про безопасность свечей, индивидуальный заказ, доставка и контакты.

Данные заказчицы стоят настоящие: Telegram `t.me/Nina.G1999`, почта `nina.gercik@mail.ru`,
отправка в ПВЗ Ozon. Телефона и адреса нет, потому что их заказчица не давала: заказы идут в
Telegram, и кнопка «Написать в Telegram» ведёт туда из шапки, первого экрана, блока про свечи и
секции контактов.

Четыре обещания в бегущей строке и в тёмном блоке взяты из её карточки дословно: безопасный
состав, эстетика в каждой детали, подарочная упаковка, индивидуальный подход.

## Картинки: что заменить

Файлы в `assets/img/` — это **сгенерированные фоны-драпировки** в фирменной палитре, не фотографии
товара. Фотостоки закрыты сетевой политикой окружения, в котором собирался шаблон, поэтому ни одна
чужая фотография сюда не попала и не подделывалась.

Для бренда, который продаёт предметы, фотография это главное. Два ваших снимка уже стоят: розовый
набор ведёт разворот «Свечи», жёлто-мятный ведёт «Декор», из каждого вырезан второй кадр для
накладки в углу плиты. Остальные места ждут съёмку:

| Слот | Что снять | Размер | Кадрируется |
|---|---|---|---|
| `portrait-pair` | пара «кот и фигурка» | 1600×1000 | 3:2, плита |
| `portrait-hand` | фигурка на ладони | 900×900 | 1:1, накладка |

Остальные фото, которые стоит добавить, когда дойдут руки: тёмно-красные пионы на кремовой
подставке (лучший кадр для первого экрана), семь пионов разных цветов (показывает линейку),
упаковка с открыткой.

Положите файлы в `assets/img/`, поправьте `src` и удалите рядом `<span class="slot-note">`.

## Форма

Форма проверяет поля и показывает успешное состояние локально, никуда не отправляя. Чтобы включить
отправку:

```html
<form class="form" id="order-form" data-endpoint="https://ваш-обработчик">
```

Уйдёт `POST` с JSON по полям `name`, `contact`, `kind`, `note`.

## Что ещё нужно от заказчицы

- **Фотографии товара** под пять слотов выше. Это главное, без них сайт не продаёт.
- **Логотип** файлом. Сейчас надпись набрана шрифтами (скрипт `Lila` плюс капитель `GERTS`), а в
  оригинале есть ещё бантик линией.
- **Отзывы.** В первой версии я написал два выдуманных. На живом магазине выдуманный отзыв это не
  заглушка, а ложное утверждение, поэтому секции отзывов сейчас нет. Появятся настоящие — вернём.
- **Цены или вилка цен**, если их показывать.
- **Текст «Обработка данных»** описывает фактическую работу формы, а не является юридическим
  документом. Перед запуском покажите юристу и при необходимости дополните.

## Проверено

Светлая и тёмная тема, 1440 и 390 пикселей, контраст WCAG AA без провалов в обеих темах, один
`h1`, уровни заголовков без разрывов, все изображения с `alt` и размерами, все поля формы с
подписями, навигация в одну строку и 72 пикселя высотой, первый экран помещается в окно, видимый
фокус с клавиатуры, валидация формы, ничего не остаётся невидимым при `prefers-reduced-motion`.
Проверялось в Chromium через Playwright.

Анимации: заголовок выезжает построчно, секции появляются по мере прокрутки, бегущая строка
останавливается по наведению, карточки приподнимаются, фон первого экрана и широкая полоса живут
на скролле. Всё на IntersectionObserver и CSS scroll-driven animations, ни одного scroll-листенера.
При `prefers-reduced-motion` движение выключается целиком.

Внешних запросов в рантайме нет: шрифты, иконки и картинки лежат рядом. Страница работает офлайн.
